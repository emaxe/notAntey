# План доработки админки notAntey

## 🔴 Часть 1: Критические баги

### 1.1 FeatureForm — неверное поле `image` → `mediaUrl`
**Файл:** `src/components/admin/FeatureForm.tsx`
**Проблема:** форма отправляет `{ image: form.mediaUrl }`, а Zod-схема и API ожидают `mediaUrl`.
**Фикс:**
- Переименовать поле в `handleSubmit` с `image` на `mediaUrl`
- Добавить поле `icon` в форму (селектор из списка: Star, Shield, Clock, Wrench, Truck и т.д.)
- Проверить что `featureSchema` в `src/lib/validations.ts` соответствует

### 1.2 CertificateForm — неверное поле `image` → `imageUrl`
**Файл:** `src/components/admin/CertificateForm.tsx`
**Проблема:** форма отправляет `{ image: form.imageUrl }`, а Zod-схема ожидает `imageUrl`.
**Фикс:**
- Переименовать поле в `handleSubmit` с `image` на `imageUrl`
- Добавить поле `category` в форму (опциональное)
- Добавить превью картинки по URL перед сохранением

### 1.3 PriceForm — несоответствие типов цена
**Файл:** `src/components/admin/PriceForm.tsx`
**Проблема:** цена отправляется как строка, а API/Schema ожидают число.
**Фикс:**
- Конвертировать `item.price` в `Number(item.price)` перед отправкой
- Добавить `type="number"` на input цены
- Валидация на клиенте: не пустое, > 0

## 🟡 Часть 2: Безопасность

### 2.1 Rate limiting на /api/auth/signin
**Приоритет:** высокий
**Реализация:**
- Middleware-level: простой in-memory счётчик по IP (5 попыток / 15 минут)
- Или: библиотека `next-rate-limit` / собственный middleware
- При превышении — 429 Too Many Requests

### 2.2 Санитизация HTML-контента
**Файлы:** `src/app/api/admin/posts/route.ts`, `src/app/api/admin/blog/route.ts`
**Проблема:** сырой HTML сохраняется без очистки → XSS при отображении.
**Реализация:**
- Установить `isomorphic-dompurify` (уже есть в dependencies)
- Оборачивать `content` и `excerpt` в `DOMPurify.sanitize()` перед сохранением в API
- На публичных страницах DOMPurify уже применён к blog/[slug], проверить остальные

### 2.3 Валидация куки в middleware
**Файл:** `src/middleware.ts`
**Проблема:** проверяется только наличие куки, не её валидность.
**Реализация:**
- Использовать `jwtVerify` из `jose` для проверки подписи JWT в middleware
- Если JWT невалиден — редирект на `/admin/login`
- Не расшифровывать payload, только проверить подпись и expiry

### 2.4 TrustHost
**Файл:** `src/auth.ts`
**Проблема:** `trustHost: true` отключает проверку хоста.
**Фикс:** Убрать `trustHost: true` или задать `AUTH_URL` явно в `.env`.

## 🟡 Часть 3: UX проблемы

### 3.1 Пагинация на всех списках
**Приоритет:** высокий (при большом количестве записей будет тормозить)
**Реализация:**
- Создать компонент `Pagination` (навигация по страницам)
- Добавить `skip`/`take` в Prisma-запросы API
- UI: "← 1 2 3 ... 10 →" под таблицей
- По 20 записей на страницу по умолчанию

### 3.2 Поиск/фильтр в таблицах
**Приоритет:** средний
**Реализация:**
- Текстовый input над каждой таблицей
- Клиентская фильтрация по title/name (для < 100 записей)
- Серверная — если записей больше

### 3.3 Мобильная версия админки
**Приоритет:** средний
**Реализация:**
- Гамбургер-меню для сайдбара на мобильных
- Сайдбар: overlay с backdrop-blur на мобильных
- Таблицы: горизонтальный скролл или карточный вид на мобильных

### 3.4 Превью картинок
**Приоритет:** средний
**Реализация:**
- В forms: mini-превью по URL при вводе (onBlur → загрузить img)
- В таблицах: маленький thumbnail вместо raw URL
- Компонент `ImagePreview` с fallback на заглушку

### 3.5 Детальные ошибки валидации
**Приоритет:** низкий
**Реализация:**
- Парсить Zod-ошибки из API-response
- Показывать ошибки под каждым полем формы
- Сейчас: generic "Ошибка сохранения"

### 3.6 WYSIWYG-редактор для контента
**Приоритет:** низкий (опционально)
**Реализация:**
- Вариант A: `@tiptap/react` — lightweight, React-friendly
- Вариант B: `react-markdown` — если контент в Markdown
- Вариант C: оставить textarea, но добавить подсветку синтаксиса HTML
